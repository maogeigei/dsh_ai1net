# 亮点详解

概述见 [README → 亮点](../README.zh-CN.md#亮点)。

## 一、进程级安全隔离

- **一人一 OS 账号** —— 每个用户一个确定性 uid，实例以该 uid 降权启动，隔离是**内核边界**，不是文件权限约定。
- **端口守卫** —— 实例只绑回环动态端口；平台按 uid 拦掉同机其它账号的直连（宿主不支持就**拒绝启动**，不静默降级）。
- **出网护栏** —— 屏蔽云元数据端点、阻断实例主动访问宿主自身，并观测新建外联。
- **浏览器信任围栏** —— 反代层洗净 `Origin` / `Referer` / `X-Forwarded-For`，Host 覆写为回环。
- **环境白名单** —— 实例 env 从白名单重建后注入该用户的值，平台密钥不进用户进程。
- **路径围栏** —— 词法包含校验 + 逐段拒绝符号链接分量，出不了用户根目录。
- **上传分级扫描** —— P0 命中直接 400 阻断；P1（动态执行 / 外联 / 敏感 env / 隐藏文件）留痕交管理员复核。
- **隔离可递进** —— 软隔离 → OS 账号硬隔离 → 端口守卫，每层独立开关。

## 二、故障自愈与状态恢复

- **崩溃熔断** —— 指数退避 + 冷却封顶（10 分钟起、最长 6 小时），坏实例不会被无限重启；冷却期内返回 `503 instance_circuit_open`。
- **按需守护** —— 守护实例只在主实例崩溃时拉起一次用于修复 ⇒ 稳态下每个活跃用户只有 1 个进程。
- **回收后无感恢复** —— 导航走过渡页、XHR 等就绪再转发、**401 透明重放**；回到页面自动唤醒并重建连接。
- **会话过期自愈** —— 实例页面注入自愈脚本（25 秒心跳 + 断流检测，连续两次失败才恢复，不误报）。
- **插件加载失败自愈** —— 不兼容插件导致的「启动即崩」会被识别并隔离，而不是无限重启。
- **并发收敛** —— 单活跃会话（后登录者胜出）+ 空闲回收（常驻上限 + TTL）。

## 三、插件与技能的受控管理

- **导入即预检** —— 依赖范围 + 导出符号双判据，不兼容默认拒投，并回显逐条依据。
- **「兼容 ≠ 可用」** —— 向浏览器交付**绝对 URL** 判为**阻断级**（托管平台上必失效，平台侧无法补救）。改法见 [插件移植指南](../PLUGIN-PORTING.zh-CN.md)。
- **启用三步** —— 探活 → 失败快照回滚 → 逐插件隔离标记：只禁掉不兼容的那个，不让整个实例陪葬。
- **内存预估** —— 按实测加载成本给预估徽章与状态条，超单实例上限时拦截并要求确认：成本取决于「装了什么」。
- **技能分两层** —— 共享层（平台内置、用户只读）+ 个人层；zip 两阶段原子替换，同名冲突需确认；装完即生效，无需重启实例。
- **官方目录一键接入** —— 约 3400 条，含中文说明回填。

## 四、模型与访问面

- **官方模型页在平台必然报错，平台自建一层** —— 官方「设置 → 模型」页要求 Host settings 镜像，而平台是「浏览器经域名访问远程服务器」⇒ 它的 `isLoopback` 判定三条皆不成立、持久化降级为内存 ⇒ 该页读不到提供方目录。平台改为**自己写文件**：把凭据库里「已启用」的条目直接落到实例的 `$DSH_HOME/.credentials.yaml` 与 `settings.yaml`。
- **只碰自己写过的** —— 平台按 `managed` 清单管理：用户自己放的密钥条目与厂家段**绝不覆盖、绝不删除**；要删只删平台写的那一行 / 那对标记之间。
- **接官方厂家目录** —— 读实例所用的**同一个** `pi-ai` 包（数据源同包 ⇒ 不会漂），列出其自带厂家（当前 39 个，含 `kimi-coding` / `moonshotai-cn` / `minimax-cn` / `zai` / `xiaomi` / `ant-ling` 等），并把「中国大陆可直连」分组置前；选中厂家**只需填一把 API Key** —— endpoint / 协议 / 模型清单全由目录提供。
- **共享与自有并存** —— 管理员可开一把共享 key 让用户零配置起步，用户也能配自己的条目并逐条启用。用户自配时**不注入平台共享 env**，用户自己的 key 优先生效。
- **越界管理不污染既有边界** —— 服务与文件 API 一律是「只能寻址自己的资源」语义；管理员要管别人时**另开一组 `/api/admin/users/:id/...` 且全部 `requireAdmin`**，而不是往原路由里塞 `if (admin)`。

## 五、可测与可回归

- **关键决策都是纯函数** —— 崩溃策略、路径围栏、patch 渲染都不依赖进程与网络：**不用起实例、不碰线上就能单测**，改完立刻能回归。
- **为回归而设计** —— 关键决策都是纯函数，行为改动可以独立推演；另**注入脚本有运行时校验**（模板求值 + `node --check`），随 `npm run verify` 一起跑。

## 六、部署与运维

- **一键部署覆盖全流程** —— 环境预检 → 依赖与构建 → DSH CLI → 环境文件 → 数据根 → 首个管理员 → 反代 → 服务 → 健康检查。
- **幂等、可预演** —— 重复执行只补齐缺失项；`--dry-run` **只打印不落盘**，且不会给出任何「已完成」式提示。
- **管理员先建、服务后启** —— 顺序写死（服务先启动会持住数据库锁），避免「部署完成却登录不了」。
- **反代自适应** —— 自动识别 `/etc/nginx/conf.d` 与面板（宝塔）的 vhost 目录；reload 依次尝试 systemd / init 脚本 / `nginx -s`，**不碰既有站点**。
- **注册 → 审核 → 登录闭环** —— 自助注册落到 `pending`，管理员审核通过后才可用。
- **每用户一个 host** —— 子域模式下会话 cookie 按用户天然隔离（同 host 多用户会互相顶会话）。

## 七、覆盖网络

- **无需入站端口** —— NAT 之后的节点从不监听端口：它只建**一条出向连接**，所有流都多路复用在它上面。中继**只绑回环**，因此增加节点不会增加公网可达面。
- **地址保持原样** —— 对调用方而言仍是普通的主机与端口，所以换传输不必动请求链路：反向代理、远程 spawner、远程文件访问一行都不用改。
- **能直连就直连，不能就走中继** —— 候选端点走**已有连接**交换（不新增端口、不新增协议），在其上尝试 UDP 通路。只有**双向**都通才算直连可用；否则判死，并**按具名原因**回落 —— 已关闭、冷却中、无地址、单向、超时。关掉它不是功能降级。
- **先定身份，再定地址** —— 四层密钥：离线根只负责授权签名者、在线签名者签发节点凭据、每节点各持一把密钥、会话用内存密钥。能不能入网**由节点自己在本地判定**，因此控制面被攻破也无法静默塞进一台节点；凡不可验证者一律带具名原因拒绝，而不是回退到共享凭据。
- **每节点一把密钥，而非共享 token** —— 共享 token 的爆炸半径是**全部节点**；改为每台各自一把，且密钥表按**逻辑名**索引，因此同一台机器名可以同时存在于两张网里。
- **网是维度，不是策略** —— 平台自己的机器与各用户的设备分属不同的网（`ops`，以及每用户的 `u:<userId>`）；会话**在结构上**就被限制在自己的网内，而不是事后靠访问清单过滤。
- **地址是一份可轮换的下发物** —— 引导顺序为「显式 env › 缓存中的签名目录 › 内置种子」，且目录**只有在受信公钥验签通过时才被采用**。目录里的种子就是轮换抓手，所以换中继不需要重装或升级客户端。
- **中继看不到明文** —— 组密钥**确定性地**加密分块：同组同明文仍得同一个块 id（组内去重照旧成立），而中继只承载密文。取回优先走直连，失败回落中继。
- **失败必具名，绝不静默** —— 拒绝入网、直连判死、目录被拒，各自都带**结构化原因**；不可验证即拒绝。它替掉的正是那类「配置错了却长得像网络不通」的故障面。
