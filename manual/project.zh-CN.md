# 开发 · 贡献 · 版本 · 人与 AI 分工

## 开发

```sh
npm install          # pnpm / npm 均可；Node ^22.19 || >=24
npm run typecheck    # tsc --noEmit
npm run verify       # 构建 + 静态校验脚本  ← 提交前跑这个
```

**改动纪律**：只改 `src/` 与 `web/`，不要改 `lib/`（它是构建产物，改了会被覆盖）；提交前必过 `npm run verify`；关键决策写成纯函数，改实现要连同断言一起改；注释写的是「为什么」—— 行为变了，注释跟着变。

## 贡献

欢迎 Issue 与 PR。

- **Bug** —— 附复现步骤、报错信息、运行环境（系统 / Node / DSH 版本）

- **PR** —— 请先 `npm run typecheck && npm run verify` 通过

### 项目信息超过上下文时怎么协作

一个会话会把它读过的、跑过的一切都带上，而之后每一轮都要再背一遍。超过一定规模，这就不是细节而是瓶颈了 —— 对应两套机制：一套管住进去多少，一套决定什么时候重开。

**清理非关键上下文。** 曾有一批工作把一个会话推到二十五万 token 以上，此后每一轮都背着这份重量。管住它的做法是：批量工作写成**脚本**跑，而不是拆成一长串单次调用；会淹没上下文的命令输出，在落地前就被拦截截断；同一个文件不在一轮轮里反复重读；上下文被当作**有上限的预算**，而不是可以无限增长的东西。优先级是有次序的 —— **单轮内的调用次数最要紧**，其次是水位，最后才是固定的提示开销。只压输出、不减调用次数，收效很小。

**接续会话。** 会话逼近上限时，工作**在新会话里继续**，而不是就地退化。承接它的是**状态文档**（做过什么、还剩什么、下一步），而不是旧对话记录 —— 重放历史只会把问题重新造出来。接续**不能比它省下的更贵**：一个新会话开头就跑几十个工具，等于什么都没赚。而且**只有判断方法已经覆盖的事才允许自动接续** —— 还有决策等人拍板时，不开接续。

**谁来决定什么。** 人定方向、并给出**判断方法**；AI 用这套方法把每一个决定推出来。方法够得到的事 —— 技术选型、命名、参数、部署细节、怎么排查、依赖哪个版本 —— AI 一律自己定，不再回头问。只有方法**够不到**的地方才停下来问：业务目标与优先级、钱与资源承诺、对外承诺与合规、只有人手里才有的凭据、文案与审美，以及影响面伸到眼前这个系统之外的事。

红线**单独提**（⛔ 不是光抛一句问题）：由 **AI 来问** —— 这件事会不会扩大可达范围、会不会打断此刻正在使用的人、会不会一次改动超过十个文件、会不会不可逆 —— 但**不能只把问题抛出去**，要一并给出**两三个具体候选**，每个都写明**优点与缺点**。**读这些候选并做判断，正是人这部分工作**：从中选一个、另提一个、或要求先进一步分析。如果每个候选都只有优点或只有缺点，那就没有可判断的东西 —— 直接定，不上抛。

技术选型**绝不**与这条问题捆在一起：它先按判断方法定好，再作为「已定项」报上来。人拿到的是**围绕目的组织好的一组建言** —— 明确知道在回答什么问题、该看什么 —— 所以读它是**带着疑问和目的去读**，而不是从头啃一份设计。

**汇报。** 先给结论，再给依据，依据只指一个来源。不确定就说不确定，不粉饰。

**范围。** 只做被要求的事。过程中发现别的问题，**先报告、不顺手改** —— 「它很小、很明显」正是计划外改动溜进来的方式。
